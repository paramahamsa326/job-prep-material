# Java and JavaScript Contract Track

## Target and length

Target contract or contract-to-hire Java backend, JavaScript/TypeScript, full-stack, integration, and ServiceNow-adjacent engineering roles. Use up to three pages when verified project detail improves vendor or client matching; three pages is a maximum, not a quota.

## Positioning

- Lead with immediate delivery capability, recent hands-on technologies, integrations, testing, and deployment readiness.
- Include project environments, responsibilities, tools, and versions only when verified.
- Use a dense but readable keyword section tied to real project evidence.
- Keep modular project bullets so each submission can be tailored quickly.
- Surface location, work authorization, sponsorship, W-2/C2C/1099/contract-to-hire preference, availability, travel, remote/hybrid/onsite preference, and rate only after confirmation.

## Content source

Use [core-profile.md](core-profile.md) for shared facts and [java-full-time.md](java-full-time.md) or [servicenow.md](servicenow.md) for verified project evidence. Expand detail; do not weaken evidence standards or import unsupported market keywords.

## Project module

For each engagement, capture:

1. Client/business capability and dates
2. Personal responsibilities and ownership
3. Java/JavaScript versions and frameworks
4. APIs, messaging, databases, and integrations
5. Cloud, containers, build, CI/CD, and operations
6. Testing and release responsibilities
7. Scale, constraints, and verified outcomes
8. Complete environment line with only used technologies

## Missing contract facts

Work authorization, sponsorship requirements, engagement type, start date, preferred locations/time zones, travel/relocation, rate tracking preference, and project-by-project technology recency remain unconfirmed.
